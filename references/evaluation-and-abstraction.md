# 评估层与机制抽取：补"做得怎么样" + 分歧地图通用化

> 核心：L3 是**做它没做的**——第三方评测明确指出该库没有配套的效果评估工具和掌握度基准：它能告诉你"做什么""持续做什么"，却无法回答"做得怎么样"。补上这一层（每个 Skill 配前后指标、跑分与回归测试）是差异最大的方向；另外，council 的"分歧地图 + 用证据裁决分歧"机制可以抽出来，用于定价、产品路线、技术选型等任何决策场景。

## 一、效果评估层（L3-e）：每个长期采用的 Skill 配三件

### 为什么"采用"和"有用"是两回事

```
无评估层的 Skill 库的典型状态（3-6 个月后）：
  装了 47 个 → 常用 8 个 → 记得 3 个 → 其中 2 个的输出质量其实在退化
  （你改过配置/换过模型/业务变了，但没人告诉你"变差了"）
根因：Skill 的"输出看起来专业"和"输出在产生价值"之间没有测量
  → 没有测量就没有淘汰 → 无效的 Skill 永远占着位置（噪音还在，价值已无）
评估层 = 给每个 Skill 配"体检"：前后指标（在不在产生价值）
  + 跑分（趋势）+ 回归测试（改动有没有把它弄坏）
```

### 三件的设计（逐个）

```
件 1：前后指标（回答"有没有用"）
  指标选择：该 Skill 作用链路上最靠后的可归因指标
    （seo-audit → 目标页引用率/收录率，不是"内容质量"；
     cro → 落地页转化率，不是"页面美观度"；
     council → 决策执行率（它的建议被采纳且执行了的比例））
  归因纪律：该指标同时被别的事影响时（转化率也受产品影响），
    标"辅助指标"而非"归因指标"——评估层不骗自己，测不准就降级
  基线采集：采用 Skill 前 2-4 周的指标均值（没采基线 = 没有"前"，
    "提升"无从谈起——先采基线再用，不是用完补采）
件 2：跑分（回答"趋势"）
  周期：月或季（指标波动大的用月，慢变量用季）
  形式：一张趋势表（周期 | 指标值 | 当期主要动作 | 备注）
  判读：
    连续上升 → 有效，继续
    连续 2 个周期不升（平或降）→ 触发淘汰评审（不是直接卸载，
      先排"指标本身失效了"的可能——归因指标失效 = 换指标，不是卸 Skill）
    上升但斜率衰减 → 查回归测试（哪次改动带来的衰减）
件 3：回归测试（回答"改动有没有弄坏它"）
  固定样例：2-3 个该 Skill 的典型输入（真实脱敏，覆盖：正常/边界/该被 veto 的）
  固定期望：每个样例的输出应该满足什么（不是逐字一致——
    LLM 输出不必逐字稳定，但关键要素必须稳定：
    "改动清单含 3 要素" / "触发 veto 1 的输入必须被拦截" / "council 必须产出分歧地图"）
  判定方法（与 validate.py 双样例纪律同构）：
    固定样例 + 固定期望判定 + 退出码（过/不过）
    每次 Skill 升级/你改提示词/换底座内容后，跑一遍回归
  产物：回归测试脚本或清单（样例输入 + 期望判定 + 最近 5 次结果）
```

### 淘汰机制的执行（评估层是淘汰机制，不是表扬机制）

```
淘汰评审（连续 2 周期不升时触发，30 分钟）：
  Q1 指标本身还有效吗？（业务变了，指标测的不再是价值 → 换指标，重采基线，
      给 1 个周期观察——换指标不等于 Skill 无效）
  Q2 回归测试最近一次过吗？（不过 = 哪次改动弄坏的，回滚那次改动，重测）
  Q3 使用频率还在吗？（没人用 = 它没进工作流，评估指标不升是必然——
      问题在使用不在 Skill，先解决"用"，给 1 个周期）
  Q4 三问都排除后还不升 → 卸载（记录：卸载日期 + 不升的证据 + 教训）
卸载的纪律：
  卸载 ≠ 否定（记录保留：这个 Skill 在 X 场景 Y 时间不升，
  场景/模型变了可以重评）
  不卸载的常见理由全是错的："装了舍不得""以后可能用得上"
  （占着位置 = 噪音；"以后用得上" = 到时会重新装，且重新装是带着新认知的）
```

### 评估层总表（库级视图）

```markdown
# Skill 评估总表 <月/季>
| Skill | 归因指标 | 基线 | 本期值 | 趋势 | 回归(近5次) | 状态 |
|---|---|---|---|---|---|---|
| seo-audit | 目标页引用率 | 2.1% | 3.4% | ↑ | 5/5 过 | 有效 |
| council | 决策执行率 | 1/4 | 2/3 | → | 4/5 过（1 次 veto 漏拦） | 观察（修回归） |
| cro | 落地页转化率 | 1.8% | 1.8% | → | 5/5 过 | 淘汰评审中（Q1：指标受新品发布干扰） |
状态枚举：有效 / 观察 / 淘汰评审 / 已卸载（保留记录）
```

## 二、机制抽取（L3-f）：分歧地图通用化

### council 的可迁移内核（剥离营销外壳）

```
council 表面 = 12 位营销大师讨论
内核 = 一个决策机制，四步：
  1. 多视角：≥2 个"框架真实冲突"的视角（不是立场，是框架——
     两个立场不同的稻草人不是视角）
  2. 独立输出：每个视角先独立给结论（不先对齐——先对齐 = 视角死了）
  3. 分歧地图：冲突点显式化（"视角 A 说 X 因为框架 P；视角 B 说 ¬X 因为框架 Q；
     分歧的根在 P 与 Q 的冲突"——分歧要归到框架层，不停在结论层）
  4. 证据裁决：主席综合时用现有证据裁决（证据能裁决的裁决；
     裁决不了的显式标"待补证据"——不硬裁决）
可迁移性判断：这个机制不依赖营销——任何"多框架冲突 + 需要看到冲突 +
证据可裁决"的决策场景都适用
```

### 抽取的三判据（场景适配检查）

```
[ ] 存在 ≥2 个真实冲突的视角
    检验：任取两视角，它们对"同一个问题"的"默认答案"相反吗？
    不相反 = 稻草人视角（硬凑的"乐观派/悲观派"是最常见的稻草人——
    真视角是框架级的：如"增长框架 vs 利润框架"对"降价"的默认答案天然相反）
[ ] 分歧点能被现有证据裁决（或能明确"待补什么证据"）
    检验：分歧地图里每个冲突点，问"我手里哪个数据能裁决它？"
    答得出 = 可裁决；答不出 = 标"待补证据 X"，先补证据再综合
    （裁决不了的冲突点先综合 = 机制被滥用为"用权威掩盖信息缺失"）
[ ] 决策者需要"看到冲突"而不是"听到共识"
    检验：这个决策如果只听到"各方一致同意 Y"，你会漏掉什么？
    漏得掉的（风险/代价/被忽略的约束）= 需要分歧地图；
    漏不掉的（纯执行型决策）= 用不上这机制，别为用而用
```

### 非营销场景 SOP 模板（三个例）

```markdown
# 分歧地图决策 SOP <场景>
决策问题（一句话，可裁决粒度）：__
视角清单（≥2，每个：框架名 + 默认倾向 + 为什么这个框架）：
  V1：__（如 价格锚定框架：用户按对比感知价值 → 默认"不轻易降价，先抬锚"）
  V2：__（如 市场份额框架：规模决定成本结构 → 默认"降价换量"）
  V3（可选）：__
独立输出（每个视角先给结论，互不见）：V1: __ / V2: __ / V3: __
分歧地图：
  D1：V1 与 V2 在"该不该降价"上冲突
      根：价格锚定（短期感知） vs 市场规模（长期成本）——冲突在时间轴
      裁决证据：__（如：当前用户价格敏感度调研数据 / 降价历史弹性）
      裁决结果：__ / 待补证据：__
主席综合（≤3 条行动，每条标注依据哪个裁决）：
  A1: __（依据 D1 裁决）
  待补证据清单（裁决不了的，补什么、谁补、多久）：__
```

**三个例的视角配置（起点参考，非模板照抄）**：
```
定价决策：价格锚定框架 vs 利润模型框架 vs 竞品心理框架
  典型分歧：降不降 / 锚设在哪 / 价格带的"心理门槛" vs "毛利线"冲突
产品路线：用户价值框架 vs 技术成本框架 vs 商业化速度框架
  典型分歧：做不做 X 功能（用户要 but 技术贵 / 商业化等不起）
技术选型：长期性框架 vs 当下速度框架 vs 团队能力框架
  典型分歧：选成熟贵 vs 新锐快 vs 团队会的（三者常两两冲突）
```

### 抽取成功的验证与两种失败模式

```
成功判据（缺一不算抽取成功）：
  [ ] 在 ≥1 个非营销场景跑完一次
  [ ] 留下分歧地图（四步产物齐全：视角/独立输出/分歧归框架/裁决或待补）
  [ ] 决策者（你或团队）反馈"看到了原本没看到的冲突"（主观但有信息量——
    如果"没看到新东西"，多半是视角稻草人了，回三判据第 1 条）
失败模式 1：视角硬凑
  症状：分歧地图里所有分歧最后都被"综合"成共识，没有任何分歧点
    被证据裁决，也没有"待补证据"
  诊断：视角是"乐观/悲观"式稻草人（立场级不是框架级）
  修复：换视角为框架级（每个视角带"它为什么默认这么想"的框架解释）
失败模式 2：裁决不了先综合
  症状：分歧点明显缺证据，主席综合还是给了确定结论
  诊断：机制被用成"用权威感掩盖信息缺失"（这比不用机制更危险——
    它让缺证据的决策显得像充分讨论过的决策）
  修复：硬规则——裁决不了的必须标"待补证据"，综合里只能写
    "在证据 X 补齐前，暂按 Y 执行（可回退）"（可回退标注 = 诚实的不确定）
```

## 三、L3 的产出物总清单（迭代计划的验收）

```
L3-e 效果评估层：
  [ ] 每个长期采用的 Skill：归因指标 + 基线 + 本期跑分
  [ ] 回归测试：固定样例（≥2，含 1 个该被 veto 的）+ 期望判定 + 最近 5 次结果
  [ ] 淘汰评审记录（如触发）
  [ ] Skill 评估总表（库级视图，含状态枚举）
L3-f 机制抽取：
  [ ] 决策 SOP 模板（视角清单/分歧地图/证据裁决规则）
  [ ] ≥1 个非营销场景的完整分歧地图（四步产物）
  [ ] 决策者反馈记录（"看到了原本没看到的冲突"）
L3 整体验收：
  库现在能回答三问：做什么（Skill 本体）/ 做得怎么样（评估层）/
  多视角怎么看（机制抽取）——三问都答得上 = L3 完成；
  答不上"做得怎么样" = 还在原项目的空位里
```

# 底座与首跑细则：product-marketing.md 怎么写、先跑什么

> 核心：**最关键的一步不是安装，是先写 .agents/product-marketing.md**——产品定位、目标受众、价值主张、竞品替代。它是所有 Skill 的底座，不写的话 AI 输出的仍是通用套话。然后装、然后**先跑审计型拿真实改动，别先跑战略讨论型**——没数据输入的战略讨论是空转。

## 一、底座四要素：写法 + 替换测试

### 要素 1：产品定位句

```
格式：「<产品名> 是 <给谁> 的 <什么>，解决 <什么问题>」
判据（替换测试）：把 <产品名> 和 <什么> 换成同赛道任何一家，
  句子仍然成立 = 套话
反例（套话）："我们是一款领先的智能营销平台，为企业提供一站式解决方案"
  （替换成任何竞品都成立；"一站式"是定位的否定词）
正例（有定位）："X 是 给 5-50 人 SaaS 团队 的 中文 AI 搜索优化工具，
  解决 内容在 DeepSeek/豆包里不被引用 的问题"
  （换一家就不成立：竞品做的可能是英文市场/别的渠道）
写不出的处理：写不出 = 你的产品定位本身没想清（这是好事，
  底座逼你面对）→ 回去做定位，不要带"待定"进底座
```

### 要素 2：目标受众（可描画的画像）

```
格式：行业 + 角色 + 规模 + 痛点（四格都填）
  行业：SaaS / 电商 / 本地服务…
  角色：谁买（决策者）+ 谁用（使用者），两者常不同
  规模：5-50 人 / 年营收 X 区间（模糊 = 不可描画）
  痛点：他们现在为这个问题付什么代价（时间/钱/机会，要具体）
判据：拿这段描述找一个真人对号——能想到具体某个人的名字 = 过
  只想得出"某类人" = 还是画像不是画像
"所有人"的处理：写"所有人"= 没写。强制选一个最痛的小群体
（先服务最痛的 20%，底座不是市场报告，是 Skill 的上下文，小而准 > 大而全）
```

### 要素 3：价值主张（对比替代的差异化）

```
格式：「用户选我们而不是 <替代方案>，是因为 <差异点>」
  差异点必须可验证（用户能自己检查：更快/更准/更便宜/更懂中文…）
判据：差异点 ≤2 个（>2 个 = 每个都不深，选最硬的 1-2 个）
常见错误：
  ✗ 把功能列表当价值主张（"支持 A/B/C 功能"≠"用户为什么选"）
  ✗ 把愿景当价值主张（"让营销更智能"用户无法验证也无法比较）
  ✓ "同样一份内容，我们的引用率是人工优化的 3 倍"（可验证、可比较）
```

### 要素 4：竞品替代（含"什么都不买"）

```
格式：「用户不买我们时，实际会：① <竞品 A>（为什么选它）② <竞品 B>
  ③ 用 <通用工具/人工>（为什么够用了）④ 什么都不做（为什么问题不痛）」
判据：④ 必须写——"什么都不做"是最强的竞争对手，
  写不出"用户为什么忍着不买"= 你不理解用户的真实痛感强度
用途：这条要素喂给 Skill 后，所有输出会自动带"对比替代"的视角
  （文案不再自嗨，而是对着替代方案打）
```

### 底座完成度检查（进首跑前的闸）

```
[ ] 四要素全部非空，无"待定/TBD/等"
[ ] 每个要素过替换测试（产品名可替换而不改变成立性 = 该要素重写）
[ ] 受众画像能对到具体某个真人
[ ] 价值主张 ≤2 个差异点且可验证
[ ] 竞品替代含"什么都不做"
全过 → 底座完成，进首跑
任一不过 → 回写底座（底座不完成禁止首跑——这是 validate.py 的硬拦截点）
```

## 二、单装 vs 全装的取舍

```
全装（npx skills add <lib>）：
  适合：你要系统性建库（做第三层"自己的 Skill 库"），且底座已完成
  风险：47 个 Skill 全在场 = AI 选 Skill 时噪音大（触发条件相近的互相抢）
单装（--skill <name>）：
  适合：验证阶段（推荐从单装开始）
  顺序：审计型先装（cro → seo-audit），跑通再装下一个
  判据：每装一个，问"它和已装的 Skill 触发条件有重叠吗？"
    有重叠且你分不清该用哪个 → 说明你的场景还没分清，先清场景再装
装的纪律：
  底座完成 之前 不装任何 Skill（装了也用不好，还产生"已经在用了"的错觉）
  每装一个 Skill 记录：装了什么版本 + 它的触发条件原文（N2 全量清单的一部分）
```

## 三、审计型 vs 战略讨论型：分类判据

```
分类判据（看 Skill 的输入依赖，不看名字）：
  审计型：输入 = 你的现状（页面/数据/文案/配置）
    → 不依赖你的战略判断，读现状就能指出问题
    → 价值信号：产出的"改动清单"你能直接执行（改哪里、怎么改、为什么）
    → 典型：cro、seo-audit、content-decay
  战略讨论型：输入 = 你的战略输入（数据 + 约束 + 目标）
    → 依赖你给的高质量输入，输入空则输出空
    → 价值信号：产出"分歧地图 + 综合结论"，且分歧能用你的证据裁决
    → 典型：marketing-council、定价讨论、定位推演
误分类高发区：
  ✗ 把"生成文案"当战略型（其实输入是产品事实，属审计型的延伸——
    产品事实从底座来，底座过了就能跑）
  ✗ 把 council 当审计型（它不读你的现状，它读你给的框架——
    没给数据就让它"分析我的业务" = 让它对着空气分析）
```

## 四、首跑验收（逐条检查）

### 审计型首跑（cro / seo-audit）

```
跑完的产出物检查：
[ ] 改动清单 ≥3 条（<3 条 = Skill 没读到你的现状，回查输入路径/底座引用）
[ ] 每条改动含三要素：改哪里（具体到页/段/字段）+ 怎么改 + 为什么（依据）
    缺一 = 该条不算数（"建议优化标题"没有"怎么改"= 无法执行）
[ ] 落地 1 条（把清单第一条真的改掉，留改前/改后对比）
    不落地 = 验证停在"看起来有用"；落地 1 条 = 验证"它指导的改动我认可"
记录（进评估层的前置数据）：
  日期 | Skill+版本 | 改动条数 | 落地的 1 条是什么 | 我的认可度（高/中/低）
```

### 战略讨论型首跑（council 等）

```
前置闸（进跑之前）：
[ ] 手里有审计型首跑的数据（改动清单/基线指标）
[ ] 手里有真实业务数据（营收/转化/渠道占比——没有具体数 = 不跑）
[ ] 决策问题写成一句话（"该先投付费还是先投内容"，不是"帮我做营销规划"）
    问题太大 = 输出必是大而空的共识套话
跑完的产出物检查：
[ ] 分歧地图存在（≥2 个视角的冲突点被显式列出，不是"各方都同意…"）
    没有分歧 = 视角没真冲突（稻草人视角）= 重跑并强化视角差异
[ ] ≥1 个分歧点用现有证据裁决了（引用你的哪个数据/哪个审计结论）
    裁决不了的标"待补证据"（这是诚实输出；硬裁决 = 机制被滥用）
[ ] 主席综合 ≤ 3 条行动（>3 条 = 综合没综合，是观点罗列）
[ ] 护栏三条执行（标注模拟/无编造引语/无真人背书暗示）——逐条核对
记录：
  日期 | 决策问题 | 视角数 | 分歧点数 | 裁决了 __ 个（引用证据：__）| 待补证据：__
```

## 五、首跑阶段的两个典型失败模式

```
模式 1："底座没写就先装了" → 输出全是套话
  症状：Skill 跑通了，输出格式对，内容像给"某 SaaS 公司"写的（没说你的产品名）
  诊断：检查输出里有没有引用底座的具体要素（定位句/受众/差异点）
  修复：回去写底座（别调 Skill——Skill 没做错，是上下文空）
模式 2："先跑了 council" → 空转 + 错误信任
  症状：council 输出了漂亮的"分歧地图"，但每个分歧都用"通常来说…"裁决
  诊断：分歧裁决没有引用你的任何具体数据
  修复：停掉 council，先跑审计型；council 进 L1 的第二个位置
  代价警示：空转一轮的 council 输出最危险——它看起来专业，
  会让你误以为"这个库真有用"，而它有用的是措辞不是判断
```

# 定制四动作细则：本土化 / 换顾问团 / 接真实数据 / 加红线

> 核心：L2 定制是**性价比最高、也是原项目最缺的**层（N4 评测已点名"Skill 不自适现有流程"）。四个动作各做取舍——**做了必须有产物，不做必须书面写理由**。取舍记录本身就是资产（它标记了"你的场景和默认场景的差异"，下次换库时直接复用）。

## 一、动作 a：AI 搜索本土化（ai-seo 的中文渠道改造）

### 为什么必须做

```
ai-seo 的默认假设：引用源面向海外 AI（ChatGPT/Perplexity/Gemini），
内容结构偏好 = 英文长文/引用密度/实体标注
中文 AI 搜索（元宝/DeepSeek/豆包/百度 AI/微信搜一搜）的引用逻辑不同：
  - 不同模型偏好不同结构（有的偏长文引用，有的偏 FAQ 块，有的偏列表）
  - 引用源池不同（海外模型少引用中文源；中文模型引用池以中文内容为主）
  - "被引用"的判据不同（海外看引用密度，中文渠道看"答案里是否出现你的实体"）
不改造的后果：按海外偏好优化的内容，在中文 AI 渠道引用率不升
（你以为做了 ai-seo，其实做了"海外版 ai-seo"）
```

### 渠道×结构偏好映射表（调研方法）

```markdown
# 中文 AI 搜索渠道映射表 <日期>
| 渠道 | 引用偏好结构（实测） | 实体露出要求 | 测试方法 | 我的结论 |
|---|---|---|---|---|
| DeepSeek | （实测填：如"偏 FAQ 块+列表"） | （实体需出现几次？） | 用固定问题测 N 次，记录引用情况 | |
| 豆包 | | | | |
| 百度 AI | | | | |
| 元宝 | | | | |
| 微信搜一搜 | | | | |
```

**调研方法（每个渠道 30 分钟，别靠猜）**：
```
1. 定 5 个固定测试问题（你产品核心场景的问题，跨渠道统一）
2. 每个渠道问 5 次，记录：答案里引用了什么内容/什么结构的内容被优先引用
3. 对比：被引用内容的共性结构（FAQ？长文？列表？带小标题？）
4. 映射表填"实测"列（不填实测 = 凭印象改造 = 改造无效）
改造产物：
  - 映射表（上）
  - 改造后的 ai-seo 配置/提示词（引用源换成中文渠道、结构偏好按映射表）
  - 验证：改造前后各跑一次固定 5 问题，引用率对比（进 L3-e 评估层）
```

## 二、动作 b：换顾问团（advisor-template 改造 + 两级标准）

### 改造流程

```
1. 读原模板：references/advisor-template.md 的字段结构
   （每位顾问：身份 + 框架/立场 + 冲突来源 + 观点样例 + 护栏）
2. 选你的顾问团（12 位可增减，核心是"框架之间真冲突"）：
   判据：任取两位，他们的框架在"同一个决策问题"上会给出相反建议吗？
   不冲突的两位 = 占位，换掉（12 位大师的价值在冲突，不在人数）
   来源：你行业里真实的方法论持有者（书/课程/公开演讲可查的）
   或你自己团队里"真有两套做法"的人（走私有顾问标准，见下）
3. 逐位填模板：每位 4-6 条"框架要点"（不是语录，是决策规则：
   "遇到 X 类决策，我倾向 Y，因为 Z"——规则可迁移，语录不可迁移）
4. 冲突自检：拿 3 个你真实的决策问题过一遍，
   ≥2 对顾问给出相反建议 = 冲突成立；普遍同向 = 团队视角没建起来，重选
```

### 两级标准（validate.py 逐条拦截）

```
公众人物（公开可查的方法论持有者）：
  标准：每条观点可溯源（出处 = 书/演讲/访谈 + 定位到章/分钟/页）
  执行：
    [ ] 每条观点后带出处（格式：《书名》第X章 / 某演讲某段 / 某访谈）
    [ ] 溯源不到的观点删掉（宁可这位顾问"话少"）
    [ ] 抽查：随机 3 条观点，打开出处核对原文意思一致（意思被转述走样 = 重写）
  为什么严：公众人物"可能说过但查不到"= 不可用。
    查不到 ≠ 没说过，但查不到 = 无法验证 = 在你的系统里等价于编造
私有顾问（你行业/团队里真实的人）：
  标准：观点必须由你提供（你访谈/转述/有书面记录），AI 绝不能编造
  执行：
    [ ] 每条观点标注来源方式（"2026-09 访谈记录" / "其内部文档第X节"）
    [ ] AI 的角色 = 组织你提供的内容，不是"替他说"
    [ ] 识别编造：顾问输出里出现"你没提供过"的立场/案例/数据 = 编造信号
        （测试方法：拿一条你确定没提供过的立场，看它是否"合理地被生成"——
        能生成 = 护栏没生效，修提示词）
  为什么严：私有顾问的"编造"比公众人物的更危险——
    公众人物编了是学术错误，私有顾问编了是"替真人表态"，责任在你
共同红线（两类都适用，与 N3 护栏一致）：
  输出标注模拟 / 禁编造引语 / 不暗示真人背书
```

### 产物清单

```
[ ] 新顾问清单（每人：身份类型[公众/私有] + 4-6 条框架要点 + 出处/来源方式）
[ ] 冲突自检记录（3 个决策问题 × 相反建议对数）
[ ] 改造后的 advisor 配置（替换原模板）
[ ] 编造测试记录（1 条"未提供立场"的生成结果 + 护栏是否拦住）
```

## 三、动作 c：接真实数据（1-2 个 loop 先跑通一个闭环）

### loop 选择的判据矩阵

```
从 43 个 loop-catalog 里挑，四判据打分（各 1-3 分，选总分最高 1-2 个）：
  数据源已有：GA4/搜索资源/CRM/工单——你不用新建数据管道（新建=工程不是循环）
  频率可承受：loop 的触发频率（日/周）你能持续看，不会三天后腻
  错了可恢复：loop 的动作（提醒/生成草稿/调权重）可逆
  痛感明确：这个 loop 盯的问题你现在真的在痛（不痛 = 没人看 = 循环死）
原文例：ranking-drop watch（盯排名下跌）/ content-decay（盯内容衰减）
  两者都适合"数据源已有（搜索资源）+ 频率周级 + 动作可逆（生成优化草稿）"
反例（常见选错）：
  ✗ 挑"最酷的"loop（自动化程度最高但数据源要新建的）
  ✗ 一次挑 5 个（同时上 = 出问题无法归因，且每个都浅）
```

### "跑通闭环"的验收点写法（配置好了 ≠ 跑通了）

```markdown
# loop：<名字> 闭环验收
数据源：<GA4 视图 / 搜索资源项目 / CRM 表>（已连接：是/否）
触发：<频率 + 触发条件（如"排名跌出前 10"）>
判断：<loop 产出什么判断（如"3 个页面跌出前 10，疑似内容衰减"）>
动作：<loop 建议/执行什么（如"生成优化草稿 → 进待办"）>
回看：<效果回看方式（如"优化后 2 周排名是否回前 10"）>
闭环证据（跑通 = 走完一次全链并留档）：
  <日期> 触发（真实数据触发，不是手动模拟）→ 判断（__）→ 动作（__）
  → 回看（__，可写"待 2 周后补"但触发-判断-动作三段必须当天真实走完）
验收判据：
  [ ] 触发是数据驱动的（不是"我手动让它跑了一次"——手动跑 = 测试，不算闭环）
  [ ] 五段（数据源/触发/判断/动作/回看）全部有真实值，无"配置好但未跑"
  [ ] 留档（上面格式存档，进 L3-e 评估层的数据源）
```

### 第二个 loop 的节奏

```
第一个 loop 稳定运行 2 周（连续 2 次真实触发都走完闭环）再上第二个
  判据"稳定"：两次触发里，动作段没有需要你人肉补逻辑的地方
  （每次都要你人肉补 = loop 没适配你的流程，先修第一个，不是加第二个）
同时上两个以上的唯一例外：两个 loop 数据源完全不同且互不干扰
（即便如此，出问题归因成本翻倍——默认纪律仍是"先跑通一个"）
```

## 四、动作 d：加红线（行业合规约束进 veto list）

### veto list 条目格式（机器可读）

```markdown
# veto list <你的行业/业务>（写进 Skill 配置，不是写进 README）
| # | 触发条件（可判定的描述） | 动作 | 依据 |
|---|---|---|---|
| 1 | 内容含"最/第一/国家级"等绝对化用语 | 拦截，不生成/不发布 | 广告法第9条 |
| 2 | 医疗类表述含疗效承诺（"治愈/根治/有效率达X%"） | 拦截 | 医疗广告审查规定 |
| 3 | 金融类表述含收益承诺（"保本/稳赚/X%收益"） | 拦截 | 金融营销宣传规范 |
| 4 | 蹭热点对象属悲剧/灾难/政治/危机类 | 拦截（newsjacking loop 自带此 veto） | 品牌风险 |
| 5 | <你的行业特有约束> | 拦截/转人工 | <出处> |
```

**格式纪律**：
```
[ ] 触发条件可判定（"含 XX 词"✓；"语气不当"✗——不可判定的条件 veto 不生效）
[ ] 动作明确（拦截/转人工/降级为草稿，不是"注意"）
[ ] 依据带出处（法规名/内部规定编号——出事时这是你的免责记录）
[ ] 写进 Skill 的配置/护栏段（AI 每次生成前能读到的位置）
    写在文档里 AI 读不到 = veto 不存在
```

### newsjacking 例子拆解（原项目自带 veto 的参考实现）

```
newsjacking loop（蹭热点内容）自带 veto：悲剧/政治/危机类热点不碰
拆解它的结构：
  为什么这三类：
    悲剧 → 消费灾难 = 品牌永久污点（不可逆，且舆论反噬与内容质量无关）
    政治 → 立场站队 = 用户基本盘风险（不可逆，且无法用"内容好"洗）
    危机 → 趁乱 = 被视为发国难财/灾难财（同上）
  共性：错误后果不可逆 且 与内容质量无关（写得多好都没用）
  → 你的 veto 条目也应该优先覆盖"不可逆且与质量无关"的失败模式
    （可逆的失败用"人工复核"处理，不可逆的才用"拦截"——
    拦截过度 = 循环瘫痪，拦截不足 = 事故，按不可逆性分配严格度）
```

### 取舍记录（不做也必须写）

```markdown
L2 动作 d 取舍：
  做：veto list 5 条（上表），已写入 <Skill 配置位置>
  不做：<例：行业无特殊合规——已查：广告法通用条款/无医疗金融表述>
  复查条件：<例：进入医疗器械类目时重审本条>
```

# skill-lib-iterate

开源 Skill 库（以 marketingskills 为实例）的「事实核对 + 三层迭代」方法论：真正价值不在"装上 47 个 Skill"，而在它给出的可复制 **Skill 工程范式**（触发条件 → 工作流 → 输出规范 → 交叉引用 → 护栏）。

一句话：**先核对（N1-N4），再底座（product-marketing.md），先审计后战略，定制四动作，最后补它没做的（效果评估 + 分歧地图机制抽取）——跳层是"装了一堆没效果"的全部原因。**

## 方法论底座（marketingskills 事实核对）

- 项目属实：coreyhaines31/marketingskills，Corey Haines（Conversion Factory 创始人），MIT 可商用
- Star 数是曲线上的点不是快照：32.9k(v2.6.0)→36.3k→39.4k→42.5k→47.1k(2026-09)，"一夜爆火"是内容号话术
- 图里 4 个 Skill（ai-seo / marketing-loops 43 循环 / marketing-psychology 30+ 行为模型 / marketing-council 12 人模拟顾问团）描述基本准确，但库实际 47 个（v2.8.0）现 v2.9.0
- 要打折：council 是人格模拟（输出标注模拟/禁编造引语/不暗示真人背书）；Skill 定义固执不自适工具栈，生产落地前必做定制；安全扫描 2/3 通过
- 真正空位：没有效果评估工具和掌握度基准——能答"做什么"，答不了"做得怎么样"

## 解决什么

| 痛点 | 本技能的做法 |
|---|---|
| "42.9K Star 一夜爆火"该信吗 | N1-N4 事实核对：Star 轨迹 ≥3 锚点才有斜率（仅快照=话术，引用必须带时间戳）；宣传清单≠全量清单（47 vs 4）；模拟类护栏读原文；评测限制项=迭代必做项 |
| 装了一堆 Skill 没效果 | 底座先行：product-marketing.md 四要素（定位/受众/价值主张/竞品替代含"什么都不做"）+ 替换测试（产品名可替换仍成立=套话）；不写底座=输出全是通用套话 |
| 先跑什么 | 首跑顺序硬规则：先审计型（cro/seo-audit，≥3 条可执行改动+落地 1 条）后战略讨论型（council 前置=手里有真实数据+≥1 个分歧被证据裁决）；没数据跑 council=对着空气分析 |
| 怎么定制（原项目最缺的） | 四动作各做取舍：中文 AI 搜索本土化（5 渠道×结构偏好实测映射表）/换顾问团（两级标准：公众人物可溯源+私有顾问你提供+编造测试）/接真实数据（1-2 个 loop 先跑通一个闭环，"配置好了"≠"跑通了"）/加红线（veto list 机器可读，按不可逆性分配严格度） |
| 怎么知道"做得怎么样" | L3-e 评估层：每个长期 Skill 配归因指标+采用前基线+跑分（≥2 周期）+回归测试（固定样例含 1 个该被 veto 的）；连续 2 周期不升=淘汰评审（先排指标失效/回归破坏/没人用，都排除才卸载） |
| 多视角决策怎么落地 | L3-f 机制抽取：council 内核=多框架冲突+独立输出+分歧归框架+证据裁决；三判据适配（真冲突视角/证据可裁决或待补/需要看到冲突）；用于定价/产品路线/技术选型；裁决不了必须标"待补证据"，禁止硬裁决（权威感掩盖信息缺失比不用更危险） |

## 安装

复制本目录到 `~/.agents/skills/`（或你的 Skill 加载路径）即可。

## 自检

```bash
python scripts/validate.py tests/sample_good.json   # 必须 exit 0
python scripts/validate.py tests/sample_bad.json    # 必须 exit 1
```

references/foundation-first-run.md    底座与首跑细则：四要素写法+替换测试正反例（"一站式"是定位的否定词/"所有人"=没写）、受众能对到具体真人、价值主张≤2 可验证差异点、"什么都不做"是最强竞品；单装 vs 全装取舍；审计型/战略讨论型分类判据（看输入依赖不看名字）；首跑验收逐条检查（≥3 条改动+落地 1 条/分歧裁决≥1）；两个失败模式（没底座先装=套话输出/先跑 council=空转+错误信任）
references/customization.md           定制四动作细则：中文 AI 渠道映射表（固定 5 问题×5 渠道实测法）；换顾问团改造流程+两级标准逐条执行（溯源格式/私有顾问来源方式/编造测试："拿一条你确定没提供过的立场看它是否被生成"）；loop 选择判据矩阵（数据源已有/频率可承受/错了可恢复/痛感明确）+"跑通闭环"验收点（手动模拟跑的不算闭环）；veto list 条目格式（可判定/动作明确/带出处/写进配置）+newsjacking veto 拆解（不可逆且与质量无关才用拦截）
